Claude Code Secret Guard

A small safety net that stops API keys, passwords and secret files from reaching Claude by accident. One script sets it up on your machine in a few seconds, and one command removes it.

Installer v1.4.0 macOS · Linux · Git Bash / WSL No admin rights needed

Install it

On a company laptop where IT has installed it, you don't need to do anything. It's already active for every user and can't be turned off. The steps below are for trying it yourself before then.

Open a terminal and run these three commands. They download the installer from our GitHub releases, check it hasn't been altered, and run it.

curl -fsSLO https://github.com/NUTechnolgyInc/claude-secret-guard/releases/latest/download/install-secret-guard.sh
curl -fsSLO https://github.com/NUTechnolgyInc/claude-secret-guard/releases/latest/download/install-secret-guard.sh.sha256
shasum -a 256 -c install-secret-guard.sh.sha256 && bash install-secret-guard.sh

The check should print install-secret-guard.sh: OK. If it doesn't, the installer won't run, so don't run it by hand. On Linux or Git Bash, use sha256sum -c in place of shasum -a 256 -c.

Then restart Claude Code. Run /hooks inside Claude Code and you should see two secret-guard hooks listed.

You only need bash, which macOS and Linux already have. On Windows, use Git Bash or WSL. If anything else is missing, the installer sets it up for you, and asks first before using a package manager or sudo. Add --yes to approve those automatically.

What the installer does

It runs these steps in order and stops at the first problem. It only touches the ~/.claude folder in your home directory.

  1. Checks your machine and sets up what's missing

    Reads your username, machine name, OS and Claude Code version. If jq is missing, it downloads the official release and verifies its checksum. It also repairs common settings.json mistakes (comments, trailing commas, a stray byte-order mark) and fixes Windows line endings.

  2. Tests the guard, and fixes it if a test fails

    Runs 26 built-in tests in a temporary folder, using only fake keys. If any fail, it works out why, tries other grep/sed tools on your machine, installs GNU versions if needed, and runs the tests again. If they still fail, it tells you the likely cause and nothing on your machine is changed.

  3. Installs the hook script

    Copies the guard to ~/.claude/hooks/secret-guard.sh. Claude Code runs it before each message you send and before Claude reads, writes or runs anything.

  4. Updates your Claude Code settings

    Backs up ~/.claude/settings.json, then adds the two hooks and a few file-read rules. Your existing settings, hooks and rules are kept. Running the installer again updates it without creating duplicates. Finally it runs the installed hook once to check that it blocks a key and lets normal messages through.

  5. Sends an install report

    Posts a short record (who, which machine, which version, did the tests pass) so we can see who has it installed. See exactly what is sent below. If the server can't be reached, the install still completes.

What it stops, and what it lets through

Blocked In your messages

  • AWS, GitHub, Slack, Google and Stripe live keys
  • Anthropic and OpenAI style sk-… keys
  • Private key blocks and JWTs
  • Database URLs with a password in them
  • Lines like DB_PASSWORD=… or api_key: "…" with a value of 16 or more characters

Blocked For Claude

  • Reading or running commands on .env files, .pem, .key, .p12, .pfx, id_rsa, id_ed25519, credentials.json, ~/.aws/credentials and secrets/ folders
  • Writing a key into a file
  • Showing you a question form. Claude asks in plain chat instead, because form answers skip the check.

Allowed Still works

  • .env.example, .env.sample and .env.template
  • Code that reads variables, such as process.env.API_URL
  • Placeholders like [REDACTED]
  • Normal questions about passwords, auth or keys

When a message is blocked you'll see a 🔒 warning and the message is not sent to Claude. Replace the value with a placeholder and send it again.

Try it

After restarting Claude Code, type this message. It contains AWS's public example key, which is not a real credential:

my key is AKIAIOSFODNN7EXAMPLE

It should be blocked. You can also ask Claude to read a .env file (refused) and a .env.example file (works).

Never sent: your keys, your files, your settings, your prompts, or anything from the block log. To skip the report entirely, run bash install-secret-guard.sh --no-report.

The local block log

Each block is written to ~/.claude/secret-guard.log on your machine with the time, your username, what was blocked and which rule fired. It never records the key itself, and it stays on your machine.

If a key gets through anyway

No filter catches everything, and the guard doesn't cover the claude.ai website or the mobile app. If a real key ends up anywhere it shouldn't:

  1. Rotate it now

    Revoke the key in the provider's console and create a new one. Deleting the chat doesn't undo the leak; rotating does.

  2. Tell security

    Say which key it was (its name, never the value), where it went, roughly when, and whether it's rotated. Reporting quickly is always the right call.

  3. Update what uses it

    Put the new key in the vault or CI secrets and redeploy if needed. Then check the key's usage logs for anything unexpected since the paste.

Remove it

bash install-secret-guard.sh --uninstall

Run it in the folder you downloaded the installer to, or download it again first. This removes the hooks, the hook script, and only the file rules the installer added. Anything you had before stays. Your settings are backed up first, next to the original, as settings.json.bak-secret-guard-<date>. Restart Claude Code afterwards.

Questions

Something legitimate got blocked. What do I do?

Tell whoever sent you this script, with the rule name from the warning (it's also in ~/.claude/secret-guard.log). Don't include the value itself. We'll tune the rule and publish a new version. To update, run the three install commands again: they always fetch the latest version and update you in place.

Does it slow Claude Code down?

No noticeable difference. It's a short shell script that runs locally in a few milliseconds per message or action. Nothing is sent anywhere when it runs; only the installer sends its one-time report.

Why does Claude ask me questions in plain chat now?

Claude's clickable question form sends your answers straight to Claude, without passing through the secret check. The guard turns the form off so every answer you type is checked like a normal message.

Does it need admin or sudo?

No. Everything goes into ~/.claude in your own home directory.

Does this mean I can't leak a secret anymore?

No. It catches the common formats and the usual secret files, but it can't recognise every kind of credential, and it doesn't scan your git history or what you paste outside Claude Code. Keep treating secrets carefully: use placeholders and never paste real keys into any chat.

I'm on Windows. Will it work?

Yes, if you run it from Git Bash or WSL. Git Bash usually lacks jq, so the installer downloads it for you and checks it against the official checksum.

The installer stopped with an error. What now?

It only stops after trying the fixes it knows, and it always says why. Common causes are no internet access to github.com (behind a strict proxy), a folder you don't own (it shows the chown command to run), or a settings.json too broken to repair (it shows the line). If it can't tell, send the output to whoever gave you the script. Nothing is changed when it stops.
